# トラブル対応: VBA コンパイル状態の破損（イベントが軒並みエラーになる）

**実績**: 2026-07-31 SC・F_特定5講座 で発生し、/decompile で解消。

## こんな症状のときこの手順書を使う

- 「**オブジェクトまたはクラスがこのイベント セットをサポートしていません**」が出る
- 「**プロパティに指定した式 〇〇時 でエラーが発生しました**」が出る
- 起動時・行移動・保存など**あらゆるイベントでエラーになる**（特定の処理だけではない）
- **ブレイクポイントを置いて F8 で進めるとエラーが出ない**（デバッガを通すと直る）
- Access を**閉じて開き直すと再発する**（最適化/修復だけでは直らない）

## 原因

VBA の**コンパイル済みコード（p-code）とソースコードのズレ・破損**。
フォームモジュールの全文貼り替えやデザイン変更を短時間に繰り返すと起きやすい。
個々のコードのバグではないため、コードをいくら読んでも原因は見つからない。

## 診断のしかた

1. VBE（Alt+F11）→ デバッグ → コンパイル（別のコンパイルエラーが残っていないか確認）
2. エラー行を特定したいとき: VBE → ツール → オプション → 全般 → エラー トラップ
   - 「**クラス モジュールで中断**」: 未処理エラーをフォームモジュール内の発生行で停止
     （ダイアログではなくソースで止めたいときはこれ）
   - 「エラー発生時に中断」: On Error で握りつぶしている無害なエラーでも全部停止
     （例: Me.ActiveControl のエラー2474 は仕様どおりの無害なもの）
   - **診断が終わったら「未処理のエラーで中断」（既定）に戻す**こと。
     オペレーターの PC で VBE が開くと戸惑いのもと
3. デバッグ後に一時的に直っても、**コールドスタート（完全に閉じて開き直し）で再現確認**する。
   再発するならファイルに破損が焼き付いている

## 復旧手順（軽い順に。各段階の前にバックアップコピー）

### 1. コンパイル＋保存
VBE → デバッグ → コンパイル → 上書き保存 → 閉じて開き直して確認。

### 2. 最適化/修復
データベースツール → 最適化/修復 → コンパイル → 保存 → 閉じて開き直して確認。
※データベース構造の修復であり、コンパイル済みコードまでは作り直さない。
　これで直らなくても想定内。

### 3. /decompile（この症状の定番・最有力）
コンパイル済みコードを全部捨てて作り直させる。

1. Access をすべて閉じる
2. `Win + R` → `msaccess /decompile` → Enter（Access が空で起動）
3. **Shift キーを押しながら**対象ファイルを開く（起動時処理をスキップ）
4. VBE → デバッグ → コンパイル → 上書き保存
5. Access を閉じて普通に開き直し、もう一度「最適化/修復」
6. 再現テスト

### 4. 新規ファイルへの全オブジェクト移送（最終手段）
1. 新規の空データベースを作成
2. 外部データ → 新しいデータソース → データベースから → Access → 問題のファイル
3. 全タブ（テーブル・クエリ・フォーム・レポート・マクロ・モジュール）を全選択してインポート
4. コンパイル → テスト → 起動時設定（Access のオプション → 現在のデータベース）を手で再設定

## 予防

- モジュールの**大規模な貼り替えをする日は、作業前にファイルのバックアップコピー**を取る
- 貼り替え作業が一段落したら「**デバッグ → コンパイル → 保存 → 最適化/修復**」をセットで実行しておく
- フォームをフォームビューで開いて動かしながらのコード編集を長時間続けない
  （編集→実行を繰り返すときも、時々フォームを閉じて開き直す）
